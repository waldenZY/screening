# Screening v2：P1 补采优化与诊断

本次只调整 P1 补采执行方式。P0、P2 和 P1 初采规则不变。P1 的 L2 配额仍在初采后冻结，
`sampling.p1.target_n` 仍是配额总数的参考值。每轮的 L2 请求数仍为
`ceil(当前缺口 / 估计通过率 × safety_factor)`，最多运行 `max_rounds` 轮；现有通过率估计参数保留。

## 一轮如何执行

1. 每轮开始时固定各 L2 的计划请求数。这个数在本轮的小批之间不重新计算。
2. 每个小批对某 L2 的请求量是 `min(当前缺口, 本轮尚未使用的计划请求数)`。
   所有仍需补采的 L2 合并为一次 Stage1 提交。
3. 每批返回后立即入集通过者，更新 cluster 的 Stage1 评估数和通过数，再决定下一批的
   cluster 份额。送检前仍使用原有的概率×频次网格、MMR 和集合内去重。
4. L2 配额填满或没有未抽过的源候选时停止该 L2。本轮计划请求数用完但仍有缺口时，
   下一轮才重新估计 L2 通过率。低通过率不单独触发停止。

## cluster 份额

对当前 L2 的每个 cluster `c`，设 `R_c` 为未抽过的源候选数，`E_c` 为已经完成 Stage1 的
候选数，`S_c` 为其中通过数，`p_L2` 为本轮固定的 L2 估计通过率：

```text
p_c = (S_c + pass_rate_prior_strength × p_L2) / (E_c + pass_rate_prior_strength)
w_c = sqrt(R_c) × p_c
```

将小批名额逐个给当前 `w_c / (本轮已给该 cluster 的名额 + 1)` 最大、且还有源候选的
cluster。相同分数按 cluster ID 排序。初采与之前补采的 Stage1 结果都参与 `E_c/S_c`；
去重前被淘汰、没有进入 Stage1 的候选不参与。若本轮计划请求数不少于可用 cluster 数，
保留 V2 每个 cluster 至少探索一次的规则，但整个外层轮次只执行一次；配额提前填满时
立即停止，不为探索继续送检。原 `cold_boundary_floor` 也按外层轮次累计。

## 报告与验证

`screening_run_report.json` 和 `.md` 增加 P1 补采诊断，包含每轮计划数、实际抽样、
基础可用、类别 exact、通过与入集，以及缺口最大的 L2、损耗最多的 cluster。
`P1/supplement_summary.json` 保存逐批 L2/cluster 明细、最终 L2 缺口、源候选剩余量和停止原因。
候选剩余量仅表示未抽过的源记录数，不能解释为仍可通过 Stage1 的数量。

本地小规模闭环测试覆盖多批补采、Stage1 中断后的续跑、报告数量守恒。
真实时延、入集量和缺口变化应在同一份源数据上对照修改前后的 V2 运行结果，并结合
模型服务时延及判断波动分析，不能仅凭一次运行的墙钟时间判定补采算法收益。
