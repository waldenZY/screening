# 数据筛选链路实现技术方案 v0

> 状态：历史方案归档，用于与 v1 对照，不代表当前推荐实现。
>
> 版本边界：v0 指最早的“统一初筛—动态分布修复—分层回捞复筛—KEEP 合并”方案。历史代码在产物命名和运行目录上曾有调整，本文只固化其业务算法和运行语义。

## 1. 建设目标

v0 面向 P0、P1、P2 三个初版集合，主要解决两个问题：

1. 使用统一模型质检剔除明显不可用样本；
2. 初筛造成某些 L1 类别损失过多时，从现有周数据中回捞样本，尽量恢复初筛前的高质量类别比例。

它本质上是一套“先筛选，再修复筛选造成的分布变化”的后处理链路。目标分布不是预先固定的业务配额，而是根据本周三个集合中的高分样本动态计算。

## 2. 输入与前提

### 2.1 输入数据

- P0、P1、P2 初版 labeled 数据。
- 每条记录至少能够提供：集合、原始行号、Query/上下文、质量分、L1；L2 用于诊断。
- 统一初筛 Prompt。
- 对低保留率类别进行复筛时，可选用更宽松或类别特化的补充 Prompt。

### 2.2 数据身份

- 周数据内部以“集合 + 原始物理行号”关联模型结果。
- 合并数据时使用样本身份进行去重。
- 输出重新回查原始 labeled 记录，避免把模型审计字段写入正式数据。

### 2.3 基本假设

- 初版数据已经带有可信的质量分和 L1/L2 标注。
- 本周 P0/P1/P2 的 4～5 分数据分布可以代表期望保留的类别结构。
- 补样只在已有周数据中回捞，不依赖额外上游语料。

## 3. 总体流程

```text
三集合 labeled 数据
        │
        ├─ 统计 4～5 分 L1 基准分布
        │
        ├─ 对首层候选执行统一初筛
        │        └─ KEEP / REVIEW / REJECT
        │
        ├─ 根据初筛 KEEP 总量计算动态目标数
        │
        ├─ 按 L1 缺口规划补样层
        │        ├─ 优先回捞高分未保留样本
        │        └─ 再逐层使用 3/2/1 分样本
        │
        ├─ 对补样候选执行复筛
        │
        └─ 初筛 KEEP ∪ 补充 KEEP → screened
```

## 4. 七环节实现逻辑

### 4.1 目标分布

将 P0、P1、P2 中质量分为 4～5 的样本合并，统计各 L1 的基准占比：

```text
baseline_share[L1]
= 三集合 4～5 分样本中该 L1 的数量
  ÷ 三集合 4～5 分样本总量
```

该比例在初筛前确定，但目标数量在初筛后才计算：

```text
target[L1]
= 初筛 KEEP 总量 × baseline_share[L1]
```

因此 v0 的目标总量会随着模型初筛保留量变化，不是固定规模。

### 4.2 候选池

候选按质量分和初筛结果分层：

1. 首层候选：初版高质量样本，优先执行统一初筛；
2. 高优先级补样：首层中已经筛过但未保留的高分样本；
3. 后续补样层：按 3 分、2 分、1 分逐层回捞；
4. 已经形成补充终态或已被抽取的样本不得重复进入后续层。

这种候选池完全来自当前周数据，没有外部 Cluster 新语料。

### 4.3 初筛

三集合使用同一套 Query 可用性标准，模型输出：

- `KEEP`：可以直接进入合格数据；
- `REVIEW`：存在疑点，默认不直接进入正式集；
- `REJECT`：当前标准下不可用；
- 无法解析：历史语义中按“未保留”处理。

初筛结果既用于生成首批 KEEP，也用于统计每个 L1 的保留率。

### 4.4 分布变化

按 L1 统计初筛后的实际 KEEP 数：

```text
deficit[L1] = max(0, target[L1] - initial_keep[L1])
```

只有存在缺口的类别进入补样规划。超出动态目标的类别不再补样，但其已有 KEEP 不会被裁剪。

这意味着：

- 目标分布用于“补不足”，不用于“裁过量”；
- 所有初筛 KEEP 都进入最终结果；
- 最终分布只能接近目标，不能严格等于目标。

### 4.5 补样

每个缺口 L1 按候选层级依次抽取：

```text
高分未保留样本
→ 3 分样本
→ 2 分样本
→ 1 分样本
```

每完成一层后重新计算：

- 本层候选数量；
- 本层新增 KEEP；
- 当前 L1 剩余缺口；
- 是否需要进入下一层。

候选耗尽后允许保留缺口。由于低分层通过率不稳定，最终数量和类别比例均可能随运行结果变化。

### 4.6 复筛

补样候选需要再次调用模型。v0 允许根据类别初筛保留率切换复筛策略：

- 一般类别继续使用标准 Prompt；
- 低保留率类别可以使用更宽松或类别特化的 Prompt；
- 已有 REJECT 可能在补充阶段被重新审核。

其出发点是避免严格初筛导致长尾类别完全消失，但副作用是不同类别可能接受不同质量尺度。

### 4.7 最终选择

最终数据为：

```text
screened = initial KEEP ∪ supplement KEEP
```

合并时：

- 按样本身份去重；
- 回查原始 labeled 记录；
- 按原始集合和物理行号稳定输出；
- 不对超过目标的 KEEP 做二次裁剪。

所以 v0 中“KEEP 即正式入选”，不存在“合格但因配额已满而不入选”的状态。

## 5. 运行产物

逻辑上包含以下产物，具体文件名可能随历史实现调整：

| 产物 | 作用 |
|---|---|
| 初筛调用轨迹 | 保存请求、响应、错误和重试信息 |
| 初筛规范结果 | 保存每条初版样本的最终判断 |
| 分集合初筛 KEEP | 回查出的首批正式候选 |
| 补样任务/结果 | 保存各层候选及复筛判断 |
| 补样摘要 | 保存基准分布、保留率、目标、各层数量和缺口 |
| 分集合补充 KEEP | 仅包含补充阶段通过的样本 |
| 分集合 screened | 初筛 KEEP 与补充 KEEP 的并集 |
| Markdown 报告 | 展示各类别筛选变化与补样结果 |

## 6. 失败与恢复

### 6.1 模型工程失败

- 网络、限流、超时或服务异常按上限重试；
- 未形成有效结果的记录在恢复时继续处理；
- 下游构建必须等待当前所需结果完整。

### 6.2 业务缺口

- 候选耗尽后可以保留缺口；
- 缺口不等同于工程失败；
- 报告应展示未补齐类别及数量。

### 6.3 可复现性

复现依赖输入、Prompt、抽样顺序及运行过程。由于目标总量由初筛 KEEP 动态决定，且低保留率类别可能切换 Prompt，跨版本复现能力相对有限。

## 7. 主要局限

1. 目标分布来自三集合高分样本，不一定代表真实业务 Population。
2. 动态目标会受到模型初筛波动影响，最终规模不固定。
3. 只补不足、不裁过量，无法严格保证最终分布。
4. 回捞 REJECT 和低分旧样本，候选质量上限受初版数据限制。
5. 类别特化宽松复筛可能造成标准不一致和结果污染。
6. P0、P1、P2 共用一套分布修复逻辑，未体现三个集合不同的建设目标。
7. 所有 KEEP 自动入选，无法区分“质量合格”和“配额内正式选中”。

## 8. 与 v1 的核心差异

```text
动态 target              → 固定 quota
本周高分分布             → taxonomy Population
三集合共享补样           → 仅 P1 默认补样
回捞 REJECT/低分旧样本   → 从上游 Cluster 抽取未质检新样本
类别特化宽松复筛         → 全流程统一 QC
KEEP 自动入选            → QUALIFIED 后按配额 SELECTED
尽量填平缺口             → 缺口可作为明确业务结果暴露
```
