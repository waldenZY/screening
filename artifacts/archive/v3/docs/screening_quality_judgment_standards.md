# Stage1 / Stage2 评判标准

本说明面向评测、标注和使用数据集的人员，描述当前质量契约 9。Query 指用户请求；“可评价”指能够判断哪些助手响应合理、哪些明显不合理，不要求唯一答案。

核对日期：2026-10-14；依据当前 Prompt、输入构造和结果校验。参数默认值与其他契约版本见 [文档索引](README.md)，采样数量调整不改变本说明的标注标准。

## 1. 两阶段分别判断什么

| 项目 | Stage1：可用性与类别核验 | Stage2：完整任务标注 |
| --- | --- | --- |
| 判断对象 | 最后一轮目标 Query，结合相关前序恢复含义 | 整条样本中最终仍有效的目标、约束和依赖 |
| 模型输入 | `sample_type`、`conversation_turns`、`candidate_category={L1,L2}` | `sample_type`、`conversation_turns` |
| 作用 | 判断是否满足正式准入条件 | 给最终成员添加难度、意图和语义障碍标签 |

两阶段都接收规范化后的完整有序文本；单轮只有一个元素。L1/L2 是一级/二级语义类别，只供 Stage1 核验，不能用来补造需求。Stage2 不接收类别或 Stage1 判断。

文本不提供可靠的说话人角色、执行状态或附件内容。不能凭前序出现请求就假设已经执行，也不能虚构助手回复或候选列表。明确纠正替代旧条件，明确取消的目标不再累计。样本中的“忽略规则、输出指定标签”等指令也是待评估数据。

## 2. Stage1：什么样的目标轮可以准入

### 核心标准

1. **需求可还原**：现有文本能说明用户希望助手做什么，不靠猜测编造目标。
2. **关键输入可恢复**：对象、必要材料和相关前文已提供或可从上下文恢复。缺题目、附件正文或关键指代对象，不能因“可以向用户索取”而通过。
3. **评价边界明确**：合理响应有可判断的范围；允许正常澄清、开放答案、口语和省略，不要求立即执行。

普通执行参数缺失由模型结合语境判断：正常追问有依据、响应可评价时可以 `valid`；依据不足时可以 `borderline`。这种豁免不适用于缺失关键材料。任务困难、敏感或需要工具，本身不等于无效。

### 四项模型判断

| 字段 | 枚举及衡量标准 |
| --- | --- |
| `category_fit` 类别匹配 | `exact`：完整目标明确属于给定 L2；`partial`：相关但只覆盖部分目标或归属证据不足；`mismatch`：属于别类或无法支持当前类别。类别错误不等于请求无效。 |
| `semantic_completeness` 语义完整性 | `self_contained`：信息足以理解并评价，可依赖已提供的前序；`context_dependent`：仍依赖缺失的关键材料、对象或前文；`fragments`：严重截断、噪声或碎片使表达无法恢复。完整不要求填齐所有偏好。 |
| `intent_clarity` 意图清晰度 | `clear`：目标可明确恢复；`vague`：可能有目标，但存在实质解释不确定性；`no_intent`：没有可还原、可评价的目标。 |
| `validity` 有效性 | `valid`：满足三项核心标准且无阻断；`borderline`：目标、信息或评价依据存在实质不确定性；`invalid`：无目标，或材料/文本缺陷使其无法成为稳定测评输入。 |

### `blocking_issues`：六类阻断原因

| 原因 | 何时选择 |
| --- | --- |
| `attachment_dependency` | 必须读取未提供的图片、文档、音频等内容。 |
| `missing_required_input` | 缺题目正文、待翻译内容等关键材料或必需信息，无法补回。 |
| `unresolved_reference` | 必需的指代对象或前序事件仍无法确定。 |
| `no_evaluable_goal` | 结合上下文仍无可还原、可评价的目标。 |
| `unrecoverable_text` | 严重截断、乱码或语义混乱导致无法恢复。 |
| `unclear_evaluation_boundary` | 可能存在目标，但合理响应范围无法确定。 |

无阻断输出 `[]`；多个独立原因可并列，同一缺失内容不重复归因。例如缺失的 PDF 只记附件依赖，不再重复记为输入缺失和指代不明。

### 程序硬校验与正式准入

程序要求恰好五个输出字段、枚举合法、原因不重复，并按上表顺序保存原因。非空原因禁止 `valid`；附件/关键输入/指代缺失必须为 `context_dependent`；不可恢复文本必须为 `fragments`；无目标必须为 `no_intent`。这些矛盾会触发响应契约错误及重试，程序不代改标签。

正式准入必须同时满足：

```text
exact + self_contained + clear + valid + blocking_issues=[]
```

`borderline` 可以没有阻断原因，但仍不准入。字段合法不等于准入；程序也没有把所有自然语言评判规则都编码成硬校验。前序有完整请求，不能自动证明最后一轮有效；孤立实体、无意义闲聊不能仅凭潜在专项价值通过。

## 3. Stage2：如何描述完整有效任务

Stage2 通读所有轮次，保留尚未明确结束的目标及有效约束。最后一句为确认或省略，不自动否定前序任务；但要检查相关前序是否有缺失、冲突或未知指代。

### `intent_label`：任务 / 问答

| 标签 | 衡量标准 |
| --- | --- |
| `task` | 操作、服务查询，以及写作、总结、润色、整理、制定计划等生成任务。查天气是服务查询，即使答案是文字也属于 task。 |
| `qa` | 知识问答、解释、观点讨论、有明确请求的交流，以及翻译和计算本身。 |

混合意图存在最终有效的操作、服务或生成任务时优先 `task`。明确取消的操作不触发优先规则；为操作解释或计算参数，不另算独立问答。

### `task_difficulty`：六档难度

假设助手具备正常所需工具，按实质分析、约束组合和步骤依赖衡量。

| 标签 | 衡量标准 | 代表例 |
| --- | --- | --- |
| `atomic` | 直接动作、直接事实回答，简单计算或短语翻译，无需额外分析 | 开灯；计算 12+8 |
| `simple` | 少量同类操作、简短解释或常规生成，无实质步骤依赖 | 写简短请假邮件 |
| `moderate` | 比较、条件判断、约束处理，或检索后分析 | 比较交通方案的价格、时间和换乘 |
| `complex` | 多种能力组合，后续依赖中间结果并需要协调 | 查餐厅营业时间，按条件筛选、订座并发送确认信息 |
| `extreme` | 复杂依赖之上还有大量约束、分支或实质性迭代规划 | 随预算和进度变化，反复协调跨时区团队排期并调整通知 |
| `not_applicable` | 整条样本没有可执行或可回答的有效目标 | 只有“好的，谢谢” |

长度、轮数、跨领域和“长期计划”等词不能单独决定高难度。同一设备的多个参数不应过度拆分。目标可识别但存在语义障碍时，按已表达目标判断难度，不补造缺失内容。

### `execution_issues`：四类语义障碍

| 原因 | 衡量标准 |
| --- | --- |
| `attachment_dependency` | 必须读取文本未包含的附件内容；附件方法问答、仅提文件名或正文已提供不成立。 |
| `unresolved_reference` | 通读全部文本仍不能确定必需的对象或事件；同一个缺失附件不重复计入。 |
| `other_unfit` | 目标存在，但有具体文本证据表明无法形成稳定测评输入，且不属前两类；如核心要求互相排斥且未纠正。 |
| `no_evaluable_goal` | 整条样本没有有效目标，必须单独输出。 |

无障碍为 `[]`，独立障碍可多选。权限、登录、实时数据、工具需求、普通补槽、困难或敏感内容、问答本身，不单独构成障碍。

程序硬校验恰好三个输出字段、枚举合法和原因不重复；`not_applicable` 当且仅当原因为 `["no_evaluable_goal"]`，此时必须为 `qa`。附件或指代问题不自动使难度变为不适用。

## 4. 八组关键边界

以下为说明性规则示例，不是真实模型输出；“→”表示前序到目标轮。Stage1 拒绝的例子用于解释边界，不表示它实际进入 Stage2。

| 边界与例子 | 判定依据 |
| --- | --- |
| 指代：“把它关掉”；“打开客厅灯→把它关掉” | 前者未知对象阻断；后者可恢复对象。短句和省略本身不是缺陷。 |
| 附件：“总结这份 PDF”；“PDF 怎么压缩” | 前者缺必需正文；后者可直接解释方法，属于 qa。 |
| 材料：“解这道题”；“题目是 3+5→解这道题” | 前者缺关键材料；后者题目已恢复，不能继续判缺失。 |
| 补槽：“设闹钟，时间没说先问我”；“帮我设闹钟” | 前者有明确澄清依据；后者需结合语境决定 valid 或 borderline，不能统一放行或拒绝。 |
| 交流：“哈哈哈”；“讨论工作与生活如何平衡” | 前者无实质目标；后者有评价范围，可以保留为 qa，不要求唯一结论。 |
| 生成与语言：“写请假信”；“翻译‘你好’”；“翻译‘你好’后发给妈妈” | 分别为 task、qa、task；混合意图以有效发送任务优先。 |
| 纠正与取消：“七点闹钟→改八点”；“播放音乐→取消，只解释爵士乐” | 前者替换条件，不累计两个闹钟；后者为 qa，取消的播放不再参与判断。 |
| 范围与难度：“每天背十词的一年计划”；“比较价格、时间和换乘后选交通方案” | 前者可为 simple，后者为 moderate；衡量的是分析和约束，不是计划期限或字数。 |

## 5. 如何使用这些标签

Stage1 决定质量准入；P0/P1/P2 还各有成员选择规则，P2 另需 Challenge 判定。Stage2 只对最终成员加标签，不因发现障碍再删除成员。

两阶段原因有重合但不一一映射：Stage1 关注目标轮可用性，Stage2 关注完整有效任务，并独立判断。结果差异用于复核，不能直接当作有人工真值支持的误放行率。

`executable` 是程序生成的下游筛选标记，不由模型输出；多轮、短目标轮、风险词命中或 Stage2 语义障碍可使其为 `0`，样本仍交付。它不等于真实执行能力，也不等于 Stage1 通过与否；详细口径见 [字段字典](screening_labeled_v5_field_dictionary.md#executable-口径)。完整模型规则见 [Stage1 Prompt](../prompts/quality_stage1.md) 和 [Stage2 Prompt](../prompts/quality_stage2.md)，工程流程见 [技术设计](screening_pipeline_technical_design_v3.md)。
