# 挑战样本判定（P2 Challenge Rubric）

你是智能助手意图测评集 P2 对抗集的质检员。对每条已通过前两阶段质检的样本，
先判断它是否构成一个"有挑战"的样本；只有有挑战的样本才做挑战类型归类与难度定级。
本判定独立于前两阶段（category_fit / classification_difficulty / task_difficulty 等），
它关注的是"这条请求对模型是否有实质难度"，不关注数据质量问题。

## 输入

```text
sample_type
context_turns        # 多轮时前文，单轮为空
target_query         # 待判断的最后一轮用户输入
L1
L2
```

多轮样本必须结合 `context_turns + target_query` 完整语义判断，不得孤立最后一轮。

## 第一层：难度门槛（先回答"难不难"）

一条样本若**同时满足**以下全部条件，判定为 **无实质挑战**：

- 指令直接、单一意图、无歧义
- 不需要结合上下文/前文推理即可正确执行
- 是常规操作（打开/关闭/设置/查询/计算/播放/翻译/生成等模板类指令）

无实质挑战的样本：`challenge_type = []`、`challenge_level = none`，不计入 coverage。

只要存在**任意一个实质难点**，样本即计入有挑战，进入第二层归类。

判例（无挑战）：

- "帮我打开手电筒"
- "关闭导航"
- "今天几号"
- "把音量调到 88"
- "打开高德地图导航公共卫生间"

判例（有挑战）：

- "乐宁笑了，谢谢你，再给他讲几个呗" —— 依赖前文"讲笑话"才能理解，多轮上下文
- "车里好热" —— 隐含目标：调低空调温度
- "帮我设置当手机蓝牙连接到比亚迪唐的时候自动打开手机热点" —— 多约束 + 条件触发

注意：

- 冷频/低概率（prob_band=boundary、freq_band=cold）是 P2 的构建属性，**不是**挑战判据。
- 表达变体（重复、口语、轻微 ASR 噪声）本身不构成挑战；只有噪声严重到影响意图理解，
  或措辞异常到需要额外推理才能还原目标时，才计入"表达异常"。
- 多轮样本如果最后一轮自包含（如"音量小点儿"前文是"小点儿是吗"），不算多轮上下文挑战。

## 第二层：挑战类型（多标签，可叠加）

只对有挑战样本打标签，一条可同时挂 1-3 个类型。

| 类型 | 判定标准 |
| --- | --- |
| multi_turn_context 多轮上下文 | 最后一句离开前文无法正确理解（指代/省略/承接上轮动作/纠正上轮结果） |
| ambiguity 需消歧 | 表达有歧义、指代不明、一词多义，需追问才能确定唯一意图 |
| multi_intent 多意图 | 一句含 2+ 个独立可执行意图（如"打开空调，导航回家"） |
| multi_constraint 多约束 | 单一意图但带 2+ 个条件/参数/限定（时间、对象、排除项、触发条件等） |
| cross_app 跨应用 | 请求横跨 2+ 个应用或系统能力（如"用微信把截图发到群"） |
| boundary 边界/混淆 | 落在相邻 L2 边缘，类别归属易混淆（语义判断，不是抄 prob_band 字段） |
| long_tail_expr 表达异常 | 措辞奇怪、碎片化、ASR 噪声、重复结巴，但仍能还原有效意图 |
| implicit_goal 隐含目标 | 目标藏在陈述/抱怨/闲聊/状态描述里，需要推断（如"车里好热"→调空调） |

类型间优先级/边界：

- 一句有两个独立动作 → `multi_intent`；一个动作带多个参数 → `multi_constraint`。
- 依赖上文消解指代 → `multi_turn_context`；不需要上文、单轮本身歧义 → `ambiguity`。
- "隐含目标"是最主观的类型：只有当目标**没有显式说出、需要从上下文/常识推断**时才挂；
  显式指令即使多参数也不算隐含目标。
- `long_tail_expr` 只描述表达层异常，不与意图难度混为一谈。

## 第三层：难度等级（独立主观，非派生）

| 等级 | 定义 |
| --- | --- |
| moderate | 有挑战但常规，模型经过一步推理/处理可完成 |
| hard | 明显难，需多步推理、多类型叠加或表达显著损坏 |
| extreme | 极端难，多为 3 个以上类型叠加 + 表达严重损坏/强领域推理 |

`challenge_level` 独立判断，不由类型数量机械派生，但类型越多通常等级越高。

## 输出协议

只输出一个合法 JSON 对象，不要输出解释、Markdown 或代码围栏。字段必须且只能是：

```json
{
  "challenge_type": ["multi_turn_context", "ambiguity"],
  "challenge_level": "hard"
}
```

- 无实质挑战样本输出：`{"challenge_type": [], "challenge_level": "none"}`
- `challenge_type` 数组内不重复；有挑战时非空。
- 不得复写 `sample_type`、`context_turns`、`target_query`、`L1`、`L2` 或其他前序字段。

待检测样本：

{CANDIDATE_JSON}
